# TalkSimul 검증 기록

검증일: 2026-10-09, Asia/Seoul. 이 문서는 확인한 범위와 아직 확인하지 못한 범위를 분리합니다.

## 실행 상태

- 개발 화면: `http://127.0.0.1:5188`
- 로컬 API/빌드 화면: `http://127.0.0.1:3001`
- React 19 + TypeScript + Vite, Express 로컬 서버. Node.js 24.12.0 / npm 11.6.2.
- 실제 환경 상태: 사용자 승인 후 로컬 API 키 설정 및 유료 API 허용을 활성화했습니다. 키의 값은 문서·브라우저·로그에 기록하지 않습니다.
- 실제 `/api/hint`가 200 응답으로 영어 예문과 한국어 의미를 반환했습니다. 테스트용 짧은 합성 WAV 4개도 생성했습니다. 개인 음성은 캡처하거나 전송하지 않았습니다.
- 영어·일본어 실제 음성 연결·전사·AI 힌트·복기의 end-to-end 검증을 합성 입력으로 완료했습니다. 발견한 의미 보존·한국어 설명 문제도 같은 전사로 다시 검증했습니다. 아래 기본 자동 검사는 외부 호출을 하지 않습니다.

음성 단위 테스트는 권한 거절, 장치 없음·장치 사용 중, 늦게 도착한 마이크 정리, SDP 요청 취소, 모든 트랙·오디오·연결·타이머 해제, 힌트 후 음소거 상태 복원, 늦은 취소 응답 무시, 빈/긴 입력, 응답/연결 시간 초과, 전사 완료 도착 순서 뒤바뀜, 마지막 발화 전사 대기와 누락 경고를 검사합니다. **이 결과는 실제 마이크·네트워크 검증을 대신하지 않습니다.**

서버 테스트는 API 키와 사용 허용 플래그, loopback Host/Origin 검사, JSON 크기·문자열 제한, 데모 데이터의 실제 API 혼입 거절, 영어·일본어/난이도별 세션 설정, 부족한 발화, 허구의 사용자 문장을 반환하는 복기 거절, 제공자 실패·시간 초과, `store:false`를 검사합니다. 전송 계층을 주입해 모두 오프라인으로 실행합니다.

실제 키를 설정한 뒤 개발 서버의 `/.env`, 파일 시스템 경유 `.env` 요청이 모두 403으로 차단됨을 확인했습니다. 빌드 서버의 같은 경로는 앱 HTML을 반환했으며 자격증명은 포함되지 않았습니다. 공개 상태 API와 최종 프로덕션 JS/CSS 번들에도 키가 노출되지 않았습니다. 검사에는 노출 여부만 기록하고 키 값은 출력하지 않았습니다.

## 브라우저에서 확인한 흐름

격리된 임시 프로필의 headless Microsoft Edge에서 Playwright를 사용했습니다. 실제 사용자 프로필을 읽지 않았으며, 외부 HTTP 요청과 `/api/` 유료 POST 요청을 테스트에서 차단했습니다. Codex 내장 브라우저에서도 실제 화면을 열어 아래 주요 흐름을 수동 확인했습니다.

- 영어 자유 대화: 직접 입력한 `I goed to a café yesterday.` → 힌트 열기·발음 버튼·돌아오기 → 두 번째 문장 입력 → 종료 → 원문과 `went` 강조 복기.
- 일본어: 언어 변경 → 카페 선택 → 도전 난이도 선택 → 해당 설정과 일본어 인사 표시. 자동 테스트에서 맥락별 아이스 주문 힌트, 일본어 원문/과거형 복기까지 확인.
- 재도전 시 이전 사용자 발화·입력란·메시지가 섞이지 않음.
- 새로고침 후 세션 기록 유지, 해당 복기 다시 열기, 선택 기록 삭제.
- API 미설정 시 실제 시작 버튼 비활성. 설정이 있는 모의 상태에서도 명시적 세션 동의 전 시작 불가. 언어/모드 선택만으로 마이크를 열지 않음.
- 빈 세션의 평가 부족 안내, 저장 quota 실패 후 화면에 복기 보존·저장 재시도, 중단되어 `review:null`인 세션의 재생성.
- 기록 삭제 중 늦은 복기 응답이 도착해도 삭제한 기록을 다시 만들지 않도록 취소·가드 적용.
- 모의 기기 음성이 비동기 재생 오류를 반환하면 힌트 화면에 안내 표시. 닫은 뒤 텍스트 대화를 이어갈 수 있고, 힌트 문장은 발화에 기록되지 않음을 확인. 이 검사는 실제 소리를 재생하지 않습니다.

## 발견 후 수정한 동작 결함

1. 전사 완료 이벤트 도착순으로 발화를 나열하던 문제: 발화 생성/확정 시점에 순서를 예약하고 화면을 정렬.
2. 종료 직전 전사 누락: 마이크 즉시 중단 후 최대 1.8초 대기, 전사 미완료 메타데이터를 기록과 복기에 표시. 마지막 메시지는 React 렌더와 별개로 동기적으로 확보.
3. 복기 생성 중 삭제한 기록 부활: 요청 취소, 삭제 ID와 요청 대상 검사로 뒤늦은 저장 차단.
4. `review:null` 기록의 복기 재시도 버튼 부재: 재생성 안내와 버튼 추가.
5. 기본 개발 포트 5173 충돌: 다른 앱을 종료하지 않고 TalkSimul은 5188 사용.
6. 대화상자 키보드 이동과 Escape 후 포커스 복귀: Tab 순환과 열었던 버튼으로의 포커스 복원을 명시적으로 구현하고 검증.
7. 기기 음성의 비동기 재생 실패가 조용히 끝나던 문제: 힌트·복기 화면에 실패 안내를 표시하고, 취소된 이전 발음의 콜백이 다음 재생이나 대화 복귀에 영향을 주지 않도록 정리.
8. 이 환경에서 기기 음성이 없거나 실행되지 않는 문제: 사용자 승인 후 실제 모드에 API 음성 대체 재생을 연결. 시작 전·힌트·복기에 발음 문장의 전송과 AI 생성 음성을 안내하고, 데모의 로컬 전용 동작은 유지.
9. 실제 일본어 복기에서 과거 경험을 새로운 주문 문장으로 바꾸던 문제: 원문의 인물·행동·시간·대상·의도를 보존하도록 지시를 강화. 상황에 어긋난 발화라도 새로운 답변을 대신 작성하지 않도록 구분하고 같은 전사로 재검증.
10. 한국어 설명 대신 일본어 설명이 반환된 문제: 한국어 출력 지시와 해당 필드의 한글 포함 스키마 검증을 함께 적용. 일본어 원문·교정 예문에는 이 제한을 적용하지 않음. 같은 전사로 한국어 요약·평가 재검증.
11. 충분한 발화에 교정 제안이 없는 정상 복기를 무발화로 안내하던 문제: 평가 부족 상태와 교정 제안 없음 상태를 구분하고 원문 보존을 브라우저 검사로 확인.

## 기기 내 발음 추가 검사

격리된 임시 프로필의 headless Edge 154.0.4258.62에서 음성 목록 갱신을 최대 6초 기다린 뒤, 합성된 짧은 일본어 예문을 버튼 클릭으로 한 번 재생했습니다. 외부 요청은 차단했으며 실제 요청은 0건이었습니다. 마이크 접근, 사용자 프로필 접근, 시스템 설정 변경이나 음성 다운로드는 하지 않았습니다.

- 로컬 음성 5개가 노출됐으며 영어 음성은 0개였습니다.
- 일본어 음성 4개 중 Microsoft Ayumi를 선택했으나, 173ms 후 `synthesis-failed`를 반환했습니다. 시작·종료 이벤트는 발생하지 않았습니다.
- 이는 headless 환경에서의 실패 기록이며 일반 브라우저 창의 재생 가능 여부나 실제 청취 성공을 입증하지 않습니다. 재생 오류가 사용자에게 보이지 않던 결함은 이 검사로 발견했습니다.

이후 승인된 실행 환경의 격리 Edge에서, 네트워크를 모두 차단한 채 일본어 로컬 Microsoft Haruka 음성을 다시 검사했습니다. `start`는 454ms, `end`는 9,877ms에 발생했고 대기·재생 상태도 종료됐습니다. 초기의 제한된 실행 환경 결과를 모든 환경의 실패로 일반화할 수 없음을 확인했습니다. 영어 실제 모드에서는 API MP3의 재생 시간 진행과 종료 이벤트까지 확인했습니다. 두 검사 모두 사람의 실제 청취는 확인하지 않았습니다.
